# Configure and verify an integrator

Confirm the connected customer. Configuration/Admin access and the matching `ri:integrators.read`, `.write`, and `.run` scopes are required; an existing connection may need new consent.

1. Call `search_integrators` to find reusable definitions. `get_integrator` returns a compact overview, mapping summaries, and the conflict token. Request `sections=source,match_levels` for source/key settings, `map_item` with `map_id` for one complete mapping, or `map` with pagination. Request `definition` only for copying or explicit full replacement.
2. Resolve the target with `search_features` and discover writable fields, types, reference targets, and allowed codes with `get_fields`. Call `get_integrator_options` with `feature_code` and `sections=match_levels` for the required master/parent/target hierarchy. Suggested keys are hints, not proof of uniqueness. CUSTOM configurations require an existing populated custom dataset id and its loader; they do not use dictionary match levels.
3. When placement matters, request `get_integrator_options` with `sections=folders`, optional `parent_folder_id` and `search_text`. For SQL, request `sections=connections` to choose an existing connection/listener. Sections can be combined; folders and connections return independent `next_cursor` values, passed back as `folder_cursor` and `connection_cursor`. Credential setup and listener installation remain administrator tasks.
4. For files, obtain upload approval and call `stage_integrator_source_file` with a local `file_path`, or with `file_name` followed by multipart field `file` uploaded to the signed URL outside model context. Files accept CSV/XLSX/XLSM up to 25 MiB and expire after three days. Use `staged_file_id` for inspection, validation, saving, and runs.
5. Call `inspect_integrator_source` for sheets, headers, paged samples, distinct `value_columns`, and composite `key_columns`. Select `sheet_name` or one-based `sheet_index`, plus the actual `header_row` and `first_data_row`. Headerless input uses `header_row=0` and `first_data_row=1`. CSV becomes worksheet `Source`, preserving leading-zero identifiers and using Excel-letter columns. Supply a delimiter when needed. Key checks cover at most 5000 data rows and do not prove full-source uniqueness. Formula previews use cached values; dates and numbers retain their stored Excel values.
6. For a new configuration, build `definition` from its typed schema. Configuration properties retain PascalCase names. Set `ProcessType`, `ProcessTypeCode`, `DataSourceType`, and the applicable source settings. SQL exploration requires an approved saved source draft, then separately approved `test_connection`, `scan_headers`, or `query` runs. Bound exploratory SQL in the statement itself. Query suppresses Realinsight posting but may change the source database. Zero-row execution results are reported as errors; a header scan can inspect an empty result schema.
7. Define `MatchLevels` from master through target. Set distinct ascending `MapOrder` values for ordered composite keys within each level. Choose `NewEntityAction` explicitly: `MATCH` updates existing matches only, `INSERT` matches or creates, and `INSERTONLY` always inserts. Choose source-backed keys unique within each parent. Periodic matching supports `CURRENT`, `EARLIEST`, and `ALL`; `ALL` may select multiple periods. Verify representative target matches with entity queries and record tools.
8. Map fields on the target feature. Configure `ValueXref`, `IgnoreValues`, reference keys and `MATCH`/`ADD` behavior, and COA mappings as needed. COA references match existing charts by `ChartName` or `ChartId`. Lookup data maps require translations before applying. Unmatched source values and blank or `[SKIP]` target translations clear data values; blank or `[SKIP]` match translations retain the source key. CUSTOM loader behavior needs separate verification.
9. For updates, prefer `changes` for supplied settings and `map_patch` for targeted `add`, `update`, `replace`, or `remove` operations. An `update` supplies `changes` and preserves omitted item properties; supplied lists or COA objects replace those properties. A `replace` supplies the complete `item`. Updates require `integrator_id` and the latest `expected_conflict_token`. A complete `definition` replaces all configuration and cannot be combined with focused edits. Optional `active` preserves activation when omitted. Creates default to the integrator root unless a folder is supplied.
10. Call `validate_integrator` with the proposed configuration request. Pass `staged_file_id` to derive columns from its Excel sheet/header settings, or supply discovered `source_columns`; do not supply both. Resolve `errors` before saving and `run_errors` before applying. `can_save` permits incomplete drafts. Validation does not save, queue work, simulate posting, or guarantee key uniqueness.
11. Show source, ordered keys, match/insert choices, changed mappings, reference/value/COA options, and warnings. After exact approval, send the same configuration request to `set_integrator` with `approved=true` and `change_reason`. The compact save response includes the new conflict token and audit operation id. No extra read is needed unless another change may have occurred.
12. If scans or execution are requested, obtain approval for the exact mode/source/SQL and call `run_integrator`. Pass the returned `run_handle` unchanged to `get_integrator_run`. Status includes `available_sections` and `scan_columns`; request `headers`, `values` with a selected column, `rows`, or `logs` as available. Value scans require mapped value-list fields. Fix mappings and validate/save again before applying. Obtain separate approval for `mode=apply`. Keep the saved definition stable until execution finishes. Never automatically retry a queue request after a timeout or uncertain response.
13. Poll until `is_complete`, then inspect `completion_code`, errors, warnings, and logs. SQL extraction completion alone is not posting completion. Page bounded results with `cursor`; paging does not limit SQL execution. Verify representative target records after apply and report preview/truncation limits.

Local commands use `ri-agent integrators search|get|options|validate|set|stage-source|inspect-source|run|status`. Complex requests accept `--request-file ./request.json`; scalar flags use kebab-case. For example, poll with `ri-agent integrators status RUN_HANDLE --section logs --limit 50`.
